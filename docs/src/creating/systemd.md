# Creating systemd units

!!! tip "Enabling systemd services"

	After creating the systemd units, you will probably want to enable them, so they are executed automatically after boot.

	This can be done by running `systemctl enable --now <service-name.service>`.

!!! info "Default user and installation path"

	All the paths in this examples use the variable `$USERNAME` for the user running Cuckoo and assume the cloned git directory is located directly in the user's home folder, at `/home/$USERNAME/cuckoo3/`.

	The default username used in the `quickstart` installation script is `cuckoo`.

	If you are running **Cuckoo3** under a different user, please read the templates carefully and change the user accordingly.

## Cuckoo Rooter
### /etc/systemd/system/cuckoo3rooter.service
```systemd
[Unit]
Description=Cuckoo Network Rooter Service
After=network-online.target
StartLimitIntervalSec=150
StartLimitBurst=5

[Service]
Type=simple
# The output of "cuckoorooter --print-command"
ExecStart=/home/$USERNAME/cuckoo3/venv/bin/cuckoorooter --cwd /home/$USERNAME/.cuckoocwd/ --iptables /sbin/iptables --ip /sbin/ip --openvpn /usr/sbin/openvpn -g $USERNAME -d
# The folder where cuckoo3 is cloned to
WorkingDirectory=/home/$USERNAME/cuckoo3
# A clean path preceeded by the venv directory for cuckoo3
Environment="PATH=/home/$USERNAME/cuckoo3/venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
Restart=on-failure
RestartSec=30

[Install]
WantedBy=multi-user.target
```

This systemd service unit runs `cuckoorooter` under the `root` user. This is necessary because `cuckoorooter` needs elevated privileges to setup network routes on the system.

The unit waits for the host to be online and then tries to start the service a maximum of 5 times, waiting 30 seconds between retries. You can modify the numbers if they don't work well for you.

## Cuckoo main process
### /etc/systemd/system/cuckoo3.service

```systemd
[Unit]
Description=Cuckoo Manager Service
After=cuckoo3rooter.service # Preferably
#After=network-online.target # Alternativelly if Cuckoo-rooter not configured
StartLimitIntervalSec=150
StartLimitBurst=5

[Service]
Type=simple
ExecStart=/home/$USERNAME/cuckoo3/venv/bin/cuckoo -d
# The folder where cuckoo3 is cloned to
WorkingDirectory=/home/$USERNAME/cuckoo3
# A clean path preceeded by the venv directory for cuckoo3
Environment="PATH=/home/$USERNAME/cuckoo3/venv/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"
Restart=on-failure
RestartSec=30

[Install]
WantedBy=multi-user.target
```

## Cuckoo web
### /etc/systemd/system/cuckoo-web.service

```systemd
[Unit]
Description=Daphne ASGI Server
After=network.target

[Service]
User=$USERNAME
Group=$USERNAME
WorkingDirectory=/home/$USERNAME/cuckoo3/web/cuckoo/web
ExecStart=/home/$USERNAME/cuckoo3/venv/bin/daphne -p 9090 cuckoo.web.web.asgi:application
Environment=CUCKOO_APP=web
Environment=CUCKOO_CWD=/home/$USERNAME/.cuckoocwd
Environment=CUCKOO_LOGLEVEL=DEBUG
Restart=always

[Install]
WantedBy=multi-user.target
```

### /etc/nginx/sites-available/cuckoo-web.conf

```nginx
# This is a basic NGINX configuration generated by Cuckoo. It is 
# recommended to review it and change it where needed. This configuration 
# is meant to be used together with the generated ASGI configuration.
upstream cuckoo_web {
    server 127.0.0.1:9090;
}

server {
    listen 80;

    # Directly serve the static files for Cuckoo web. Copy
    # (and update these after Cuckoo updates) these by running:
    # 'cuckoo web djangocommand collectstatic'. The path after alias should
    # be the same path as STATIC_ROOT. These files can be cached. Be sure
    # to clear the cache after any updates.
    location /static {
        alias /opt/cuckoo3/static
    }

    # Pass any non-static requests to the Cuckoo web wsgi application run
    # by uwsgi. It is not recommended to cache paths here, this can cause
    # the UI to no longer reflect the correct state of analyses and tasks.
    location / {
        client_max_body_size 1G;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_pass http://cuckoo_web;
    }
}
```

This Nginx configuration assumes the static web root is at `/opt/cuckoo3/static`. If you changed this during install, please adjust accordingly.

If may need to add `default_server` right after `listen 80` on line 9 if you want Cuckoo to listen on all interfaces and be the default site served by nginx.

The file can be further modified to [add domain names](https://nginx.org/en/docs/http/server_names.html) and [configure HTTPS](https://nginx.org/en/docs/http/configuring_https_servers.html).

All configuration changes should be followed by a reload (`nginx -s reload`) or full restart (`systemctl restart nginx.service`) to take effect.
